# Standalone Figma master prompt

```text
Act as a senior enterprise product designer. Create a high-fidelity, accessible desktop installer wizard for “LITIT AI Desktop” called “Smart Install.” This is not marketing onboarding: it is an environment-aware diagnostic and installation tool that must feel calm, professional, modern, technical, trustworthy, and enterprise-ready.

Context: LITIT AI Desktop requires Windows 11+, macOS 14+, or Ubuntu 22.04+; 8 GB RAM; 5 GB disk; Python 3.11+; and microphone access. NVIDIA GPU and CUDA 12+ are optional. Users include a nontechnical Business User, a Developer who wants paths/logs, an Enterprise IT Administrator with privilege/proxy constraints, and an ML Engineer with multiple CUDA versions and custom model storage. Never automatically destroy or rewrite a valid Python/CUDA environment.

Design a desktop frame at 1440×900 with a restrained system-UI visual language. Use neutral light surfaces, a single blue primary action, semantic green/amber/red/blue/gray statuses, subtle borders, minimal shadow, 4/8 px radii, compact 4 px spacing grid, body text around 16 px, clear focus rings, and no excessive gradients, glassmorphism, huge headings, playful illustrations, unnecessary cards, or decorative animation. Meet WCAG 2.2 AA: keyboard order, visible focus, 4.5:1 body contrast, non-color status labels/icons, semantic error summaries, reduced-motion variants, 200% reflow intent, and minimum 24×24 targets (prefer 40 px control height).

Create a reusable component set and connected flow for: Welcome; System Scan; Compatibility Overview; Blocking Python Failure; Optional CUDA Warning; Configuration; Installation Summary; Installation Progress; Installation Failure + Retry; Health Check; Success; Advanced Diagnostics. Keep failure states inside the same wizard rather than dead ends. The step sequence is Welcome → System Analysis → Compatibility Report → Configuration → Installation Plan → Install → Health Verification → Complete.

Each status must show plain-language outcome, why it matters, next action, and expandable Technical details with detected/expected values, path/version, timestamp, command/exit evidence. Demonstrate required checks for OS, memory, disk, Python, microphone, plus optional GPU/CUDA. Show scoped retry: Python fails, user chooses a clearly labeled simulated/safe remediation, only Python rechecks, previous results and configuration remain. Show CUDA mismatch as a warning with existing CUDA preserved and CPU fallback/manual remediation. Show separate application and model locations with required/available disk. Show an installation plan listing components, paths, size, network, permissions, and environment impact. Progress uses named real phases, not invented percentages. Health verification proves config, model, microphone, backend, and overall application state before success.

Use concrete copy, not lorem ipsum. Include component variants for success, warning, blocking failure, information, in progress, disabled; checking/passed/warning/failed/remediated requirement states; buttons; inline alert; progress; remediation; technical details; location picker; configuration option; permission request; log viewer; health and completion summaries; error summary; confirmation dialog. Name layers/components systematically, use Auto Layout and variables, and annotate interaction/focus behavior. Provide a traceability page mapping persona finding → UX decision → component → behavior. Clearly label any simulated detection/remediation in prototype-only controls.
```
