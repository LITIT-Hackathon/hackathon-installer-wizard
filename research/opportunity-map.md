# Opportunity map

## Outcome: confident, verified installation

| Opportunity | Candidate response | Measure | Scope |
|---|---|---|---|
| Understand readiness before commitment | parallel system scan and compatibility summary | user correctly predicts whether install can continue | MVP |
| Explain blockers without jargon | plain cause, impact, recommended action | blocker comprehension and recovery completion | MVP |
| Preserve valid environments | non-destructive defaults; isolated/manual/CPU alternatives | no unintended runtime changes | MVP policy, stretch native remediation |
| Recover in place | scoped recheck/retry with retained state | recovery without restart | MVP |
| Choose storage confidently | install/model destinations with volume-specific space | no late disk failure | MVP |
| Review machine changes | installation plan listing size, paths, privileges, components | informed confirmation | MVP |
| Support managed networks | detect proxy/elevation and export plan | actionable handoff | MVP detection, stretch offline execution |
| Prove runtime health | invoke `--health`, map structured results, launch app | successful exit and visible evidence | MVP |
| Diagnose advanced failures | redacted logs and support bundle | faster expert/support resolution | P1/stretch |

Opportunities come from needs; responses are **architectural proposals**, not validated feature demand.
